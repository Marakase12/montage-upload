# Умный монтаж

Релиз: `studio-20260922-smart-edit-v1`. Статус: DEPLOYED (2026-09-22).

## Пользовательский сценарий

Для новых SHORT-проектов переключатель «Умный монтаж» включён по умолчанию.
Его можно выключить перед загрузкой. В LONG он недоступен: там действует
отдельный поиск фрагментов. Старые проекты не подключаются автоматически.

Первый preview создаётся по обычным настройкам проекта. Дополнительные
сокращения из предложения не применяются автоматически. После обработки
в чате проекта появляется сообщение монтажного ассистента: что предлагается
изменить, почему, длительность до и после. Применение — только кнопкой
«Применить план». Это не подтверждение публикации или финального ролика.

## Границы первой версии

- Более сильное начало по уже выполненному AI-анализу, с привязкой к началу
  предложения в расшифровке. Не переопределяет пользовательский anchor.
- Удаление длинных пауз существующим детерминированным алгоритмом.
- Произвольное удаление фраз в середине и перестановка смысла не реализованы.
- Начальное сокращение ограничено 25% исходника, удаление пауз — отдельно
  25%. Каждая правка и суммарная длительность показаны до подтверждения.
- Дополнительного вызова AI для этого плана нет: используются существующий
  analysis.json и word timestamps. Исходник не изменяется.

## Защита от ошибочного применения

Локальный smart_edit.json связывает точный план с job и SHA-256 текущих
edit_plan.json, transcript.json и preview.mp4. Изменённый/устаревший план
отклоняется. Клиент отправляет только ID плана и явное APPLY_SMART_EDIT;
произвольные действия клиента не принимаются как содержимое плана.

Проверки владельца, очередь и блокировка повторных действий остаются активны.
Повторное нажатие не создаёт вторую правку. Обычная правка инвалидирует
предложение. Ошибка подготовки предложения не отменяет готовый preview.
Новый render запускается через существующую REVISION; AI повторно не
переосмысливает уже подтверждённый набор действий.

## Выкладка и проверка

Нужны одновременно веб/API-релиз и локальный cloud_bridge версии 4,
build 20260922-smart-edit-v1. API отклоняет старый worker при попытке
забрать smart-задачу. Frontend проверяет capability smartEditProposalsVersion.
Обычные старые задачи сохраняют совместимость с bridge версии 3.

Автотесты проверяют default-on, подтверждение, принадлежность, двойной клик,
устаревший preview, подмену плана и отсутствие изменений до подтверждения.
Локальная UI-проверка использует только явно обозначенные синтетические данные.
Полный production-проход «новый ролик → предложение → согласие → новый preview»
нужно подтвердить отдельно, не применять планы к клиентским видео для теста.
