# Перенос MontageAI с личного ПК

Дата: 2026-09-22. Статус: **проектный план, не выполненный перенос**.
Новая инфраструктура не заказана, миграция пользовательских данных не запускалась.
Задачи C01–C10 ведутся в [бэклоге](COMMERCIAL_BACKLOG.md).

## Решение для первого этапа

Сохранить текущий сайт, API, PostgreSQL и S3. Вынести Python executor на одну
отдельную постоянно работающую машину; начать с одной задачи одновременно.
После доказанной стабильности увеличивать число исполнителей. Не вводить
Kubernetes и несколько очередей без измеренной необходимости.

```text
iPhone / браузер / Telegram
             ↓
      HTTPS сайт + API ───── PostgreSQL
             │                  ↑
             ├──── приватное S3 │
             │                  │
             └──── worker API ──┘
                       ↑ исходящие запросы worker
              отдельная машина исполнения
              Python / модель STT / FFmpeg
              ограниченный scratch + durable artifacts
```

Это архитектурная рекомендация, а не утверждение о выбранном тарифе. CPU/GPU,
память, диск и месячный бюджет выбираются после замеров на наших исходниках.
GPU может ускорять отдельные стадии, но не исправляет ошибки очереди и не нужен
автоматически всем стадиям.

Timeweb описывает App Platform как деплой приложения в новое контейнерное
окружение и рекомендует внешние хранилища для сохраняемых данных. Поэтому не
размещаем единственную копию jobs или моделей на изменяемом диске web-контейнера.
[Официальная документация App Platform](https://timeweb.cloud/docs/apps/how-it-works).

Текущую multipart-схему сохраняем; совместимость нужных операций подтверждается
перечнем S3 API провайдера, но сбои проверяем отдельными тестами.
[Timeweb S3 API](https://timeweb.cloud/docs/s3-storage/manage-storage/s3-guide).

## Что мешает просто скопировать папку

По текущим исходникам, без чтения секретов:

| Зависимость | Где обнаружена | Что подготовить |
|---|---|---|
| Windows FFmpeg `.exe` | `render_preview.py` | Настраиваемые пути и startup-проверка binary/filters/fonts |
| Windows file locks | `worker_runtime.py`, `telegram_queue.py`, `web_panel.py` | Убрать безусловный msvcrt; у `cloud_bridge.py` уже есть ветка fcntl, проверить весь путь |
| Локальный AI CLI | `analyze_job.py` и связанные AI-стадии | Явный AI adapter и проверенная неинтерактивная серверная авторизация |
| Модели/шрифты/музыка на диске | Pipeline/assets | Версионируемый manifest, права, checksum и предзагрузка |
| Jobs и preferences на Windows | `jobs/`, `memory/preferences/` | Durable storage и точный план переноса владельцев |
| Scheduled Tasks / PowerShell | install/start scripts | Отдельный service-entrypoint и graceful shutdown |
| Раздельные папки кода | Web Git и локальный Python | Воспроизводимый выпуск executor отдельно от его данных |

Целевой Linux worker — не готовый порт. Если сроки потребуют промежуточного
Windows-сервера, это отдельное решение с проверкой доступности, лицензирования
и бюджета. Не выдаём контейнеризацию за автоматически решённую переносимость.

## Контракт переносимого исполнителя

Следующее — **предлагаемые параметры**, их поддержка ещё не реализована:

- `MONTAGE_DATA_DIR`: рабочие jobs и журналы восстановления вне каталога кода.
- `MONTAGE_MODEL_DIR`, `MONTAGE_ASSET_DIR`: модель и проверенные assets.
- `MONTAGE_FFMPEG_BIN`, `MONTAGE_FFPROBE_BIN`: реальные исполняемые файлы.
- `MONTAGE_AI_BACKEND`: явный AI adapter, без неявной зависимости от desktop-сессии.
- `MONTAGE_MAX_CONCURRENT_JOBS`: изначально 1; лимиты памяти/диска/таймаутов обязательны.

Существующие URL API и worker-secret остаются в защищённой конфигурации. Секреты
S3/БД не нужно копировать исполнителю только ради скачивания: он получает
ограниченные по времени ссылки от API. В дальнейшем заменить общий worker-key
на индивидуальные отзываемые полномочия и явную область доступа.

Перед стартом: проверить версию протокола, место на диске, модель, FFmpeg,
поддержку ASS/шрифтов, AI-доступ и схему конфигурации. При ошибке не брать работу.
Startup-check не должен отправлять сообщения, обрабатывать пользовательский ролик
или выводить секретные значения.

STT по-прежнему использует проверенный faster-whisper и зафиксированную модель;
не скачивать другую копию автоматически при каждом запуске. При реализации STT
читать `WHISPER.md` локального проекта. Регрессии включают кириллицу и тайминги.

## Данные и повторный запуск на другой машине

Одного готового MP4 недостаточно для дальнейших правок. Нужно сохранить исходник,
его checksum, probe, transcript с таймингами, edit/reframe/music plans, точные
версии renderer/model/assets, approval и связь cloud task ↔ local job ↔ owner.

- У рабочего тома есть резервная копия, срок хранения и проверка восстановления.
- Локальные абсолютные пути не становятся публичными идентификаторами.
- Артефакты переносятся по manifest с проверкой размеров/checksum, сначала копией.
- Владельцы и гостевые области не объединяются при миграции.
- Preferences получают версию и API-контракт; два worker не должны перезаписывать
  общий JSON друг у друга. До этого остаёмся на одном исполнителе для этой области.
- Потеря lease запрещает старому исполнителю записать актуальный результат.
- Нужна привязка старых jobs к машине до переноса артефактов. Новый worker не
  должен забирать правку старого локального job, которого на нём нет.
- Историю не удаляем для «чистого старта» и не меняем approval при копировании.

## Фазы и условия выхода

1. **C01–C02: воспроизводимость и preflight.** Собрать чистый executor-release без
   `.env`, jobs и личных сессий. На чистой тестовой машине запустить проверки.
2. **R01/R09 + C03–C04: надёжный транспорт и переносимость.** Повтор complete
   безопасен, один битый job не блокирует чужой; проверить locks/paths/shutdown.
3. **C05–C07: артефакты, память и измерения.** Проверить восстановление job и
   правку после смены машины. Замерить стадии, объём scratch, RAM/VRAM и стоимость.
4. **C08: отдельный staging.** Другие credentials/БД/bucket; тестовый worker
   технически не имеет production-доступа. Платные ресурсы — после согласования.
5. **C09: управляемое переключение.** Новые тестовые проекты направить на сервер.
   Старый worker дождётся окончания работы и прекратит новые claims. Старые jobs
   мигрировать проверяемыми копиями либо явно оставить недоступными для правок
   до переноса; клиенту нельзя молча подменять результат.
6. **C10: подтверждение независимости.** Только после миграции всех поддерживаемых
   для правок jobs провести согласованный тест с выключенным личным ПК.

Критерий C10: с телефона загрузить SHORT и LONG, получить обработку, перезагрузить
страницу, запросить правку и скачать результат; отдельно перезапустить серверный
worker во время начальной обработки. Нет чужих данных, дубля задачи, потерянного
подтверждения или обращения к Windows-папке владельца. Нужен протокол результатов.

## Переключение и откат

Не гонять старый и новый worker в одной очереди до проверки протокола и доступа
к артефактам. Сначала drain, backup, проверка совместимости, затем переключение
назначения задач. При проблеме остановить выдачу новых задач, сохранить состояния
и вернуть проверенную совместимую версию. Не запускать legacy API с опасной очисткой.
Реестр attempts/approval не очищать. Автопубликацию не использовать для smoke-test.

## Деньги и внешние решения

Перед заказом машины зафиксировать диапазон нагрузки, допустимое ожидание и лимит
месячных расходов. Считать отдельно: API/БД, compute, хранение/резервные копии,
трафик и платный AI. Размер загрузки не равен длительности или стоимости работы.
Измерить несколько SHORT и LONG, а не выводить тариф из одного удачного рендера.

Домен, почта для подтверждения email/восстановления доступа, платёжный провайдер,
политика хранения и privacy-тексты — отдельные решения. Этот документ ничего из
перечисленного не подключает и не гарантирует соответствие правовым требованиям.
