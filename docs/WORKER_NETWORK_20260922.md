# Инцидент: Windows-worker терял связь с облаком

Дата: 2026-09-22. Компонент: локальный `cloud_bridge.py` в
`X:\AI\Codex\montage`. Сборка исправления: `20260922-network-v2`;
протокол bridge остаётся v3. Web/API и тарифы не менялись.

## Подтверждённая причина

Процесс был запущен, но urllib автоматически использовал локальный системный
HTTP-прокси. Контрольные запросы через него завершались TLS EOF и таймаутами.
Те же HTTPS-запросы напрямую к API проходили за 0,1–0,7 с.
Облако показывало worker OFFLINE, исходник ожидал скачивания, рендер не шёл.

Код усиливал сбой: ожидание сетевой операции до часа при передаче файлов,
backoff до пяти минут, ошибка чтения очереди правок блокировала проверку новых
видео. В диагностике возраст локального файла ошибочно представлялся возрастом
подтверждённого heartbeat.

## Что изменено

- Только запросы bridge к Cloud API и подписанным S3 URL используют отдельный
  opener с `ProxyHandler({})`. Глобальные настройки Windows/VPN/urllib, AI и
  Telegram не изменяются. Проверка TLS-сертификатов не отключена.
- По умолчанию режим `direct`. При намеренно обязательном прокси можно явно
  задать переменную окружения процесса `MONTAGE_CLOUD_PROXY_MODE=system`.
  Неизвестное значение отклоняется. Эта переменная читается из окружения
  запускающего процесса, не из `.env`.
- Таймаут блокирующей сетевой операции: API 20 с, heartbeat 10 с,
  скачивание/отправка результата 30 с. Для передачи файла это таймаут ожидания
  сокета, не лимит общей длительности скачивания большого видео.
- Пауза между неудачными опросами ограничена 60 с. Сбой списка правок не
  препятствует проверке новых видео; ошибки авторизации по-прежнему блокируют работу.
- Оборванное скачивание не становится исходником; `.part` очищается, повтор
  ограничен. Уже проверенный исходник не удаляется. Перед запуском pipeline
  повторно проверяется владение lease.
- Диагностика различает `stateAgeSeconds` и возраст последнего успешного
  heartbeat (`heartbeatAgeSeconds`), показывает сборку и режим транспорта.
  Сетевые ошибки имеют безопасную категорию, без URL/ключей/сырого traceback.
- Owner isolation, lease fencing, запрет автоматического повтора actions и
  обязательный approval не менялись.

Основание выбора транспорта: [официальная документация Python urllib.request](https://docs.python.org/3.12/library/urllib.request.html#urllib.request.ProxyHandler).

## Проверки

- Полный локальный набор: 86 тестов, 85 успешных, 1 необязательный render-тест
  пропущен. Среди новых проверок: изоляция от системного прокси, таймауты,
  отсутствие утечки текста ошибок, независимость очередей, неполное скачивание,
  корректный возраст heartbeat. Интернет в unit-тестах не используется.
- Старый worker остановлен штатно через `--request-stop`, не принудительно.
  Новая сборка запущена существующей задачей `MontageAI Cloud Bridge`.
- Реальный исходник 335 205 945 байт скачан полностью, создан один локальный job,
  транскрипция завершилась; сервер подтвердил worker ONLINE/busy.
- Реальный SHORT завершён: `preview.mp4`, 127 142 957 байт, 105,2 с,
  1080×1920, H.264/AAC. Pipeline выполнил техническую проверку;
  дополнительный независимый ffprobe подтвердил контейнер/потоки/длительность.
  Локальный статус `READY_FOR_REVIEW`, ошибок нет. Загрузка результата и
  финальный status-запрос подтверждены API; только после этого journal стал
  `COMPLETE`. Исходник повторно загружать клиенту не потребовалось.
- Первая сборка v1 выполнила эту сквозную обработку; v2 дополнительно закрывает
  необработанный IncompleteRead ответа API/отправки файла. После окончания job
  выполнен штатный перезапуск на v2. Это не визуальная оценка качества монтажа
  и не ручная проверка скачивания на клиентском iPhone.

## Безопасная диагностика и перезапуск

Из `X:\AI\Codex\montage`:

```powershell
.\.venv\Scripts\python.exe cloud_bridge.py --diagnostics
```

`managedLockHeld=true` доказывает наличие процесса, но не доступность облака.
Проверять `heartbeatConfirmed`, свежесть `heartbeatAgeSeconds`, `phase`, `stage`
и состояние конкретного задания. `stateAgeSeconds` не заменяет heartbeat.

Для обновления сначала запросить остановку:

```powershell
.\.venv\Scripts\python.exe cloud_bridge.py --request-stop
```

Дождаться освобождения managed lock и завершения задачи, затем:

```powershell
Start-ScheduledTask -TaskName 'MontageAI Cloud Bridge'
```

Не запускать вторую копию, не обнулять очередь, не редактировать owner/lease
вручную и не перезапускать машину во время монтажа. Журнал сохраняет проверенный
локальный результат для повторной доставки, без повторного рендера.

## Что этим не решено

Личный ПК должен оставаться включённым и иметь сеть. Это не SLA и не перенос
executor на сервер. Полная недоступность сети по-прежнему задержит задания.
Идемпотентное завершение загрузки (R01) и остальные задачи из плана стабильности
остаются отдельными работами.
