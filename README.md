# Montage Upload Service

Страница для загрузки больших исходников. Поддерживает локальный режим и облачную схему GitHub Pages → Timeweb App Platform → Timeweb S3.

Облачный режим также поддерживает MontageAI pipeline: сайт сохраняет задачу в S3,
локальная Windows-машина забирает MP4, MOV или MKV через защищённый worker API, отправляет на
сайт стадии обработки и загружает готовый preview обратно в S3. На сайте можно
написать составную правку обычным текстом и явно подтвердить выбранный preview.
Подтверждение создаёт локальный `final.mp4`, но никогда не запускает публикацию.

## Запуск

```powershell
cd X:\AI\montage\upload-service
npm start
```

После запуска откройте `http://127.0.0.1:3020`.

Файлы передаются частями по 8 МБ, сохраняются без загрузки целого файла в память и могут быть продолжены после обрыва: достаточно снова выбрать тот же файл.

## Настройки

Переменные окружения:

- `PORT` — порт, по умолчанию `3020`.
- `HOST` — адрес, по умолчанию `127.0.0.1`. Для локальной сети можно установить `0.0.0.0`.
- `UPLOAD_DIR` — папка назначения, по умолчанию `X:\AI\montage\inbox` при текущем расположении проекта.
- `MAX_FILE_SIZE` — максимальный размер одного файла в байтах, по умолчанию 20 ГБ.
- `CHUNK_SIZE` — размер части в байтах, по умолчанию 8 МБ.
- `UPLOAD_TOKEN` — необязательный ключ доступа к API.

Пример запуска для локальной сети с ключом:

```powershell
$env:HOST = '0.0.0.0'
$env:UPLOAD_TOKEN = 'замените-на-длинный-случайный-ключ'
npm start
```

Пользователь вводит этот ключ через кнопку «Ключ доступа» на странице.

### Локальная проверка интерфейса студии

```powershell
node scripts/studio-preview.mjs
# или без демо-аккаунта:
node scripts/studio-preview.mjs --guest
```

Откройте `http://127.0.0.1:3032`. Это изолированные тестовые данные, а не ваши
проекты: сервер не обращается к Timeweb, S3 или worker и не сохраняет загруженные
байты. Тестовый MP4 намеренно пуст — воспроизведение настоящего результата нужно
проверять отдельно. Не используйте этот сервер для реальных роликов.

Новый сценарий студии:

- Выбор исходника и согласие не создают проект и не отправляют файл.
  Только «Начать монтаж» запускает создание и передачу.
- MP4, MOV и MKV проходят предварительную проверку расширения/размера;
  фактическую проверку медиаданных по-прежнему выполняет worker.
- Новое видео получает исходные настройки, а не незаметно наследует прошлые.
- Формат выбирается до запуска: 9:16 (1080×1920, по умолчанию),
  1:1 (1080×1080) или 16:9 (1920×1080). `processing.aspectRatio`
  проходит через API в `upload_options.aspect_ratio` локального worker.
  Старые задания без этого поля сохраняют 9:16; неизвестный формат отклоняется.
  Рендер, кадрирование, текстовые слои и проверка MP4 используют выбранный размер.
  LONG сохраняет выбор для дочерних фрагментов, но сам анализ не запускает рендер.
  Для внедрения нужны обновления сайта/API и локального worker вместе.
- Заметка при создании сохраняется как brief, но не является AI-командой.
  Рабочие параметры задаются переключателями; свободные правки отправляются
  через существующий revision API после появления результата.
- Просмотр, черновик правки и скачивание собраны в одном окне. Обновление
  статуса не сбрасывает воспроизведение; новую версию нужно открыть явно.
- Кабинет получает подтверждённый статус из изолированных S3-префиксов.
  Непроверенные или просроченные результаты не выдаются как готовые к скачиванию.
- LONG пока показывает найденные моменты и причины выбора. Выбор кандидатов
  для рендера требует отдельного API; интерфейс не рисует неработающие кнопки.
- Approval остаётся отдельным подтверждением. Публикация не запускается.

### Надёжность облачной очереди — первая фаза

- Worker отправляет heartbeat раз в 15 секунд, независимо от длительности
  распознавания или рендера. Сайт считает его онлайн при heartbeat моложе 60 секунд.
  `/api/health` и `/api/pipeline` возвращают только `worker.state`, `lastSeenAt`,
  `phase`: без идентификаторов процессов, токенов или путей локальных файлов.
- Начальная обработка получает аренду на 120 секунд. Heartbeat продлевает её;
  медленная стадия сама по себе не делает задание брошенным. После остановки
  процесса можно забрать просроченную начальную задачу новой попыткой — максимум
  три попытки подряд, затем FAILED и явный ручной повтор.
- Состояние аренды хранится в S3. Все переходы задачи сериализуются транзакционным
  advisory lock в уже подключённом PostgreSQL, в том числе между репликами API.
  В production без этой БД новые переходы отклоняются; in-memory lock только
  для изолированных тестов/разработки. Новая схема БД и дополнительные сервисы не нужны.
- Каждая попытка имеет отдельный ключ результата. Потерявший аренду процесс
  не может заменить текущий статус/результат; старый presigned PUT пишет только
  свой уже неактивный объект. Подтверждение сохраняет ровно выбранный preview.
- `/api/pipeline/:taskId/retry` доступен с токеном соответствующего проекта
  только для FAILED начальной обработки при доступном и непросроченном исходнике.
  Повторное нажатие не создаёт дубликат. Срок хранения исходника при повторе
  не продлевается. `retryable`/`retryReason` в pipeline управляют кнопкой сайта.
- REVISION и APPROVE не переигрываются после таймаута или перезапуска.
  Неопределённый результат действия требует проверки; подтверждённый готовый
  результат не заменяется запоздалой ошибкой. Старые PROCESSING-задания без
  аренды также не забираются автоматически.
- API и Windows bridge нужно обновлять совместно: сначала убедиться, что старый
  bridge свободен, остановить его, развернуть API, затем запустить новый bridge.
  Маркер этой версии API: `studio-20260922-recovery-v1` в `/api/health`.

## Перед публикацией в интернете

Облачный backend находится в `timeweb-api`. Он создаёт временные сессии и подписанные multipart-ссылки, поэтому файлы передаются напрямую в Timeweb S3. Инструкция по переменным и деплою находится в `timeweb-api/README.md`.

Локальный bridge находится в рабочем MontageAI-проекте:

```text
X:\AI\Codex\montage\cloud_bridge.py
```

Ему нужны только URL облачного API и общий `WORKER_SECRET`. S3-ключи остаются
только на Timeweb и не копируются на Windows.

После заполнения двух локальных переменных мост можно установить в автозапуск:

```powershell
& 'X:\AI\Codex\montage\install_cloud_bridge_task.ps1'
```
